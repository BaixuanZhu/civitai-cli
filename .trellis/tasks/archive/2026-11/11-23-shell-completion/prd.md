# completion: new civ completion <shell> subcommand

## Goal

Add civ completion bash|zsh|fish|powershell emitting shell completion scripts: static completion of command names and flags, dynamic completion for enum-valued flags (--sort, --type, --period, --base is free-form, proxy schemes), plus install hints and a line in the global help page.

## Requirements

- **R1** — `civ completion <shell>` prints a static completion script for the shell to stdout, exit 0. Supported shells: `bash`, `zsh`, `fish`, `powershell`.
- **R2** — Coverage: all user-facing command names (search, show, vet, sync, tags, login, logout, proxy, skill, upgrade, completion itself, version, help); per-command flag names including the five global flags; enum-valued flag values where the flag is enumerable: `--sort` (search), `--period` (search), `--type` (search; repeatable), `--format` (sync), `--scope` (skill), `--platform` (skill), proxy schemes for `civ proxy set` (http/https/socks5/socks5h). Free-form values (`--base`, `--tag`, `--user`, `--token`, `--key`, `--timeout`, URLs) get no value completion.
- **R3** — Scripts are static text shipped as Go consts (hand-written per shell, generated by the implementer once) — no runtime subprocess callback to `civ`, so completion stays instant and offline.
- **R4** — Bare `civ completion` (no shell) prints the command's help page, stdout, exit 0 (friendly default, matching the tool's other bare forms like `civ proxy`). An unknown shell name is a usage error: message listing valid shells on stderr, exit 1. `--json` keeps the runner's default semantics (script text still goes to stdout).
- **R5** — Drift guard: a unit test builds each command's real `flag.FlagSet` through its `register` function and asserts every registered flag name appears in the completion spec; and every command in main's dispatch table (minus the internal `unbootstrap`) is covered. The spec table is the single source the scripts are written against.
- **R6** — Docs: the command's help page shows install one-liners per shell (eval/source line); `README.md` gains a Completion section; root usage lists `completion`; CHANGELOG `Unreleased` entry.

## Acceptance Criteria

- [ ] **AC1** `civ completion bash|zsh|fish|powershell` each print a non-empty script containing the command list and `_civ`/`#compdef civ`/`complete -c civ`/`Register-ArgumentCompleter` anchors respectively; exit 0.
- [ ] **AC2** Unknown shell: exit 1, stderr lists the four valid names; bare `civ completion`: help page, exit 0.
- [ ] **AC3** Drift-guard test passes today and fails if a flag or command is added without updating the spec.
- [ ] **AC4** Integration: `run completion_bash completion bash`, `run completion_pwsh completion powershell`, `run completion_bad completion tcsh` (exit 1), `run completion_kw completion help`.
- [ ] **AC5** The command follows the new-subcommand recipe (design-principles P3): own file in `internal/cmd`, pure `run*`, help const, dispatch entry in `main`, usage line; no net/http anywhere.
- [ ] **AC6** `go build ./...`, `go vet ./...`, `go test ./...` green; scripts are valid enough for each shell's syntax check where available locally (bash -n; zsh/fish/pwsh best-effort manual smoke per parent AC5).

## Constraints

- Zero new dependencies; the command renders text only (`internal/report` not needed — raw script consts).
- All-English; completion descriptions in English.
- Out of scope: API-driven dynamic completion (model names, tag names); shell startup-file auto-modification (docs only, no `civ completion install`).

## Notes

- Feedback item 4. PowerShell matters: the primary distribution channel on Windows is install.ps1 + per-user PATH.
- The scripts should complete global flags after the command name (the tool's only accepted position) and must not complete flags before the command word.
